# Meetly — WebRTC видеособеседование 1 на 1

Учебный проект на HTML, CSS и JavaScript без сборщика и дополнительных зависимостей.

## Функции

- Подключение к signaling WebSocket преподавателя: `wss://inai-col3.fishrungames.com/signaling/`
- Обмен `offer`, `answer` и ICE candidates.
- Передача видео и аудио через WebRTC.
- Включение и отключение собственной камеры и микрофона.
- Завершение звонка и обработка сообщения `{ "type": "peer-left" }`.
- Повторное подключение к новому собеседнику после его входа.
- Детерминированный выбор инициатора через handshake `hello` / `hello-ack`: только один участник создаёт offer.

## Запуск локально

1. Распакуйте архив.
2. Откройте папку проекта в VS Code.
3. Запустите `index.html` через расширение **Live Server**.
4. Разрешите сайту доступ к камере и микрофону.
5. Откройте адрес Live Server во втором окне браузера или в режиме инкогнито.
6. Нажмите «Подключиться» в обоих окнах.

Камера обычно доступна только на безопасном origin: `https://` или `http://localhost` (Live Server использует localhost).

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub.
2. Загрузите в корень репозитория `index.html`, `style.css`, `app.js` и `README.md`.
3. Откройте **Settings → Pages**.
4. В разделе **Build and deployment** выберите **Deploy from a branch**.
5. Выберите ветку `main` и папку `/ (root)`, затем нажмите **Save**.
6. Откройте опубликованный HTTPS-адрес сайта в двух браузерах и проверьте звонок.

## Как устроена сигнализация

Оба клиента отправляют `hello` с уникальным ID. Получив `hello`, клиент отвечает `hello-ack`. Клиент с лексикографически меньшим ID создаёт `offer`, второй возвращает `answer`. ICE-кандидаты отправляются сообщениями `candidate`. Все эти сообщения пересылаются сервером второму клиенту без необходимости хранить состояние комнаты на фронтенде.

Сервер по условию поддерживает только двух подключённых клиентов: при входе третьего он отключает первого. Поэтому одновременно тестировать нужно ровно в двух окнах.

## Важное ограничение сети

В проекте указаны публичные STUN-серверы. В обычных сетях этого часто достаточно для учебной демонстрации. В некоторых корпоративных, мобильных или строго ограниченных сетях для гарантированного соединения требуется TURN-сервер; адрес и учётные данные TURN в задании не предоставлены.
